# Figma → code token map

Generated by `/figma-bridge:onboard` and maintained by hand afterwards. This is the repo's own
translation table: every value an agent carries from a design lands here first, so no hex code
and no raw pixel value crosses from Figma into the codebase.

Regenerate the raw material with `get_variable_defs` on a frame, or `search_design_system` with
`includeVariables: true`. Keep the *decisions* — the right-hand column — by hand.

## Colour

| Figma variable | Code |
| --- | --- |
| _e.g._ `Color/Base/White` | _e.g._ `bg-white` / `COLORS.white` |

## Spacing and radius

| Figma variable | Code |
| --- | --- |
| _e.g._ `Numbers/Distance/Distance 16` | _e.g._ tailwind `4` |

## Typography

Text styles map onto the codebase's typography components, never onto raw font sizes — that is
what keeps a design change to one place.

| Figma text style | Component |
| --- | --- |
| _e.g._ `Headers/Headline Large` (28) | _e.g._ `<Headline size="large">` |

## Constraints worth writing down

Record the places where the type system is narrower than the design, because an agent will
otherwise reach for a `className` override to get past it. For example: a `weight` prop that is
only valid at one `size`, or a closed union of text colours. A colour the union lacks is a
design-system change to raise, not an override to sneak past.
